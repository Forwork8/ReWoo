For technical evaluators

How this engagement actually runs.

The method behind the offer — what is measured, what “done” means, and what lands in your hands. Terms are finalized per engagement in the written plan.

Method

  • Milestone shape. Discovery, written plan, build in demoable increments, shadow run, pilot handover — each gate has entry criteria.
  • Evaluation harness. The task set and escalation paths are tested continuously during the build, not bolted on at the end.
  • Pilot instrumentation. Usage, success rate and cost are measured from the first real task, so the review reads numbers, not vibes.

Acceptance criteria

  • End-to-end acceptance. The agent must pass the agreed task set, including the cases where it must escalate instead of act.
  • Honest reporting. The evaluation report includes failures and edge cases; that is the point of a pilot.

You receive

  • Handover package. Repository, runbook, evaluation report, and a working session with your team.
  • Continuation options. Scale, iterate or stop — decided at the pilot review, with the numbers on the table.

Exclusions

FAQ

Asked about this engagement.

What if we do not know which workflow first?

Then the AI Readiness Audit is the right starting point — building the wrong workflow first is the expensive path.

Do you keep the keys afterward?

No. Code, configuration, credentials, and docs transfer at handover. If you want ongoing support, that is a separate, optional arrangement.

What if the agent turns out not to be feasible?

Evaluation results are delivered honestly — including a stop recommendation if the quality bar cannot be met. The milestone structure means you learn this early, not expensively.
